## Core Principles

### I. The Public API Is a Contract

The library's public API is whatever is reachable through its declared entry points (`main`: `lib/index.js`, `typings`: `lib/index.d.ts`). **Anything reachable is owned**; anything not reachable is internal and may change at will.

- The `main` + `typings` fields are the single source of truth for what consumers can import. Adding a new public export is an additive change; removing or renaming one is a breaking change.
- `src/index.ts` MUST re-export the entire public API explicitly. Wildcard re-exports (`export * from './module'`) are acceptable at the entry file only when every symbol in the module is intentionally public; if any symbol is internal, it MUST be excluded from the wildcard.
- Internal modules (helpers, types not meant to be imported externally) MUST NOT be reachable through `src/index.ts`.

### II. Semver Is Not Optional

The library follows semantic versioning strictly:

- **MAJOR** when a public type changes shape, a public function changes signature, behavior, or thrown errors in a way consumers can observe, or a runtime requirement (Node version, peer dep major) increases.
- **MINOR** for additive public API or new optional behavior.
- **PATCH** for bug fixes that preserve the contract.

Releases MUST update `CHANGELOG.md` describing the change in user-facing terms before any publish to npm.

### III. Library Code Reads No Environment

Library code is **environment-agnostic**: it MUST NOT read `process.env` directly (except the single top-level `process.env.FORCE_COLOR` assignment in `src/index.ts`, which is a documented side effect), MUST NOT depend on the presence of files at fixed paths, and MUST NOT assume a specific runtime sandbox unless explicitly documented.

- Configuration MUST come through function arguments, options objects, or factory functions — not implicit globals.
- Consumers of this library pass configuration (app credentials, account, workspace, region) into the constructors and clients; the library MUST NOT reach for those values globally.

### IV. The Build Output Is Deterministic

- The output directory (`lib/`) MUST be reproducible from source — running `yarn build` on a clean checkout MUST yield the same artifacts.
- Build outputs MUST NOT be committed to the repository; CI publishes them. `lib/` MUST be listed in `.gitignore`.
- The `files` array in `package.json` is explicit: `["lib/", "gen/"]`; do not rely on `.npmignore` to redact accidentally-included files.
- Type declarations (`*.d.ts`) MUST be emitted by `tsc` (`declaration: true` is already set in `tsconfig.json`) and MUST cover every public export.

### V. Tests Cover the Public API

- Every public export MUST have at least one test that exercises it through the public entry point — not by reaching into internals.
- Tests run via Jest. The test matrix targets Node.js `>=8` per `engines.node`; dropping a Node version is a MAJOR change.

## Stack-Specific Standards

- **Language**: TypeScript `^4.4.4` with `strict: true`; inline suppressions (`// @ts-ignore`, `// eslint-disable`) require a justifying comment.
- **Runtime**: Node.js `>=8` (per `engines.node` in `package.json`); the CI setup-node step uses Node 22 for publishing.
- **Package manager**: `yarn`; `yarn.lock` MUST be committed; CI MUST install with `--frozen-lockfile`.
- **Entry points**: `main` → `lib/index.js`, `typings` → `lib/index.d.ts`, `files` → `["lib/", "gen/"]`.
- **Linting**: `tslint` (configured in `tslint.json`). Inline disables require a justifying comment. <!-- TODO(team): tslint is deprecated upstream — consider migrating to ESLint with `@typescript-eslint` when the team has capacity. -->
- **Observability**: this library provides Koa-based server utilities and OpenTelemetry tracing for VTEX IO apps. The `@opentelemetry/api` and `@vtex/diagnostics-nodejs` packages are runtime dependencies and MUST be kept aligned with the consuming service's SDK versions.

### Build: `tsc`

- The build is `tsc` against `tsconfig.json`; no bundler is involved. Output target: `es2019`, module format: `commonjs`.
- `declaration: true` is set in `tsconfig.json` — type declarations are part of the deliverable.
- The `gen/` directory contains JSON schema generated by `yarn gen` (`typescript-json-schema src/responses.ts PublicAppManifest`). Schema generation MUST be re-run whenever `PublicAppManifest` changes; CI runs `ci:build` which includes `yarn gen`.
- Avoid runtime-only compilation tricks (decorators with metadata, `tsc-alias` rewrites) unless documented; they make the published artifact harder to consume.

## Operational Constraints

- The canonical commands for this repository are:
  - Build: `yarn build` (runs `yarn clean && tsc`).
  - Watch: `yarn watch` (runs `yarn clean && tsc --watch`).
  - Lint: `yarn lint` (runs `tslint -c tslint.json './src/**/*.ts'`).
  - Format: `yarn format` (prettier — run before lint with `yarn format-lint`).
  - Tests: `yarn test` (Jest). CI variant: `yarn test --ci --coverage`.
  - Schema gen: `yarn gen` (re-generates `gen/manifest.schema`); CI runs it as part of `ci:build`.
  - Pre-publish check: `prepublishOnly` runs `scripts/publishLock.sh`, which guards against non-CI local publishes.
- Publishing is CI-driven via the `publish-npm.yml` workflow (manual dispatch from CodeArtifact to npmjs). Local `npm publish` is reserved for emergency hotfixes and MUST be documented in the changelog.
- Adding a runtime dependency MUST be a deliberate decision; review every new dependency for license, maintenance status, and whether it could be a peer dep instead. Koa and OpenTelemetry packages are intentional runtime deps because the library ships Koa middleware and OTel instrumentation.
- Peer dependencies MUST declare a version range that reflects the actually-tested matrix.
